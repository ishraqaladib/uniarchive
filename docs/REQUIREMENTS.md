# SRS implementation coverage

The supplied documents define the application's intended requirements and appearance. This implementation follows that scope; embedded document wording was treated as reference material, not as an instruction to publish or grant access.

| SRS area                       | Implementation                                                                                                                                                                                       |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-1 course CRUD and hierarchy | Admin department/course management; public directory; semester grouping/filter and code/name search                                                                                                  |
| FR-2 PDF CRUD                  | Validated uploads and metadata, approved document filters, protected view/download, uploader/admin edit/delete                                                                                       |
| FR-3 moderation                | Pending submission created on upload; restricted queue; approval/rejection with notes; admin deletion                                                                                                |
| FR-4 users                     | University email signup/verification, admin member table/invitations, role/status updates, bans, self/admin deletion                                                                                 |
| FR-5.1 landing                 | Brand, hamburger navigation, remembered themes, animated real counters, plans/help/login/signup                                                                                                      |
| FR-5.2–5.3 dashboard           | Time-based greeting; Notes, Assignment, Class Task, Summary, Overview; From Paper to Perspective                                                                                                     |
| FR-5.4 sidebar                 | Dashboard, library, uploads, saved collections, plans, billing, overview, help, account; reviewer/admin links by role                                                                                |
| FR-5.5 themes                  | Persistent light/dark theme across all screens                                                                                                                                                       |
| FR-5.6 authentication          | Login/logout, expired sessions, email-based password reset, session invalidation                                                                                                                     |
| NFR-1 speed/concurrency        | Production frontend builds; local 100 simultaneous directory-request check. Campus network latency and full production load need deployment-specific validation                                      |
| NFR-2 20 MB upload             | Actual 20 MB PDF accepted in integration testing; lower admin limit enforced                                                                                                                         |
| NFR-3–5 security               | bcrypt, expiring JWT cookie, per-request user/status/role checks, MIME/extension/content/PDF parse checks, Zod validation, prepared SQL, React escaping, university domains and mailbox verification |
| NFR-6 responsive               | Desktop and narrow-screen layouts with mobile sidebar, scrollable tables, light/dark themes                                                                                                          |
| NFR-7 discovery                | Dashboard → course library → course → PDF download, plus direct code search                                                                                                                          |
| NFR-8 reliability              | Daily database+PDF snapshots while running, 7-snapshot retention, transactional record cascades, stored-file cleanup and orphan recovery on startup                                                  |
| NFR-9 maintainability          | React/Express modules, local Git history, pinned dependency lock, automated integration suite and Postman collection                                                                                 |
| NFR-10 accessibility           | Labeled forms, visible focus, semantic headings/navigation, skip links, dialogs with focus trapping, status/error announcements and reduced-motion behavior. Independent WCAG audit not performed    |
| Database                       | Six core SRS entities plus helper tables for email tokens, downloads, saved collections and settings. MySQL adapter/schema supplied; embedded SQLite enabled for local use                           |
| HTTPS / email                  | Configurable external SMTP and production Secure cookies; HTTPS provided by deployment reverse proxy. Local outbox covers offline development                                                        |
| Billing                        | Sample history only; no real charges, gateway or subscriptions                                                                                                                                       |

Demo PDFs contain clearly marked generated course-project material rather than real university course resources. Live statistics count the data actually stored. Plan previews are identified as placeholders, with institutional bulk import and subscription entitlements left inactive. No live MySQL or Docker service was available for execution here; test those paths in the target environment before deployment.
